# Determine the minimum cross-run and cross-stack corpus diversity

## Question

Which existing non-sealed Quantis runs qualify as independent environments
for a cross-run or cross-stack JEPA, and what minimum additional stack,
schedule, intervention, and repetition coverage must be collected before
representation fitting, selection, calibration, and held-out-stack evaluation
can support an identifiable topology-portability claim without environment,
schema, or source-corpus leakage?

## Answer

The current evidence is not a cross-stack corpus. Seven candidate-corpus
records resolve to two open primary campaigns but only one substantive
checkout-stack family. Derived feature tables and event caches inherit their
source campaigns; replica counts and repeated runs are within-stack evidence;
result-bearing confirmation captures remain ineligible.

Freeze the strict exploratory floor at six environment-distinct stacks:

- three fit stacks;
- one selection stack;
- one calibration stack;
- one untouched evaluation stack.

Each stack must completely cross five portable intervention/target mechanisms,
three canonical topology levels, three workload-shape families, and at least
three separately reset matched treatment-control pairs per cell. This is 135
pairs per stack. Three is a diagnostic floor; a later promotion collection
must use a pilot-powered count.

The existing action-dynamics campaign can become one fit stack after adding
the two missing workload families. That costs 90 minimum pairs. Five new
complete stacks cost 675 pairs. The minimum strict-tracer increment is
therefore 765 matched pairs / 1,530 trajectories.

The six-stack design supports only a result on one named unseen stack. A
repeated bounded claim requires ten stacks under `3 fit / 2 selection /
2 calibration / 3 sealed evaluation`. No finite count establishes universal
portability.
